# Secure Password Manager — Checkpoint 3 Draft

## Introduction

This application is a command-line password manager implemented using C. This program allows a user to create an encrypted vault, open it using a master password, and add credentials to an existing vault. The application works with the OS user accounts and does not have any accounts of its own.

## Implementation

The application uses libsodium for the vault. Using the master password, the Argon2id function generates a key for encryption and decryption using the XChaCha20-Poly1305 algorithm. For an interactive terminal, the CLI hides the password input and obscures stored passwords when listing the entries. When adding a record, the application opens the current vault, stores an updated version of it and replaces the file only if the write operation succeeded.

## Security Analysis

Before reading the vault file, the application verifies its owner and permissions. The CLI also rejects an unsafe working directory, which belongs to another user or writable by the group or others. Events generated by the CLI include the operation name and the result and do not include the credential fields.

The `make test` suite was successful. Tests included checking record persistence, rejecting wrong master password, The API and CLI tests also ran with AddressSanitizer and UndefinedBehaviorSanitizer without reported errors in the tested scenarios.

However, the ownership check is made, but testing with a second OS account is not carried out. At the same time, updates by two processes under the same OS account are not covered by the lock.

## Conclusion

Checkpoint provides an encrypted local vault, automation tests for API and CLI, and logging. The obtained test results allow establishing the behavior of the above scenarios; however, it does not guarantee security coverage.
